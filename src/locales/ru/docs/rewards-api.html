API наград

Своя логика на покупку награды: например, бот крутит рулетку или меняет сцену в OBS. Ключ — тот же, что у событий (студия → 🔔 События).

Сразу узнавать о покупке

Подключись к API событий (глава «События», страница «API событий») и слушай event с type: "reward". В vars есть rewardSlug и redemptionId.

Список покупок по HTTP

У каждой награды свой адрес — его копирует кнопка 📋 API в карточке:

GET https://partywatcher.de/api/rewards/<канал>/<награда>?status=new
Authorization: Bearer ТВОЙ_КЛЮЧ
ПараметрЧто это
statusnew, done или refunded. Без него — все.
afterВремя ISO, например 2026-10-13T18:00:00Z: только покупки после него.

Ответ — до 100 покупок, новые сверху:

[{ "id": "…", "reward": "coinflip", "user": "viewer123", "userId": "…",
   "cost": 50, "message": "", "status": "new", "createdAt": "…" }]

Отметить покупку

POST https://partywatcher.de/api/rewards/<канал>/<награда>/<id>/done
POST https://partywatcher.de/api/rewards/<канал>/<награда>/<id>/refund

done — выполнено, refund — вернуть зрителю поинты. В студии статус меняется там же.

КодЧто значит
200Готово.
401Ключа нет, он неверный или от другого канала.
404Нет такой покупки.
409Покупку уже отметили раньше.

Ключ передавай только в заголовке Authorization, не в адресе — иначе он попадёт в журналы.
