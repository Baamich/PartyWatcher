Connect your own bot or Twitch / VK chat

Already have a bot that reads your Twitch or VK chat? No need to rewrite it: just let it forward messages to our site with one HTTP request. Your channel chat and OBS will then show messages from all platforms at once, labelled with where they came from.

How it works

  • Their chat → ours. The bot gets a message on Twitch or VK and sends POST https://partywatcher.de/api/chat/send with your chat key. The message appears here with a source label (twitch, vk…) and nickname color.
  • Our chat → theirs (optional). The bot connects to our chat over Socket.IO with the same key and forwards new messages to Twitch or VK from its own account.
  • The chat key is in the studio: “Stream management” → “Chat API” (details in Chat in OBS, steps 1–2). It is not the stream key and not the events key.

If your bot has an “HTTP request” or “Webhook” step

Many ready-made bots and apps can send a request without code. Set it up like this:

FieldValue
MethodPOST
URLhttps://partywatcher.de/api/chat/send
HeaderAuthorization: Bearer pwc_… (your chat key)
HeaderContent-Type: application/json
Body{"text": "message text", "username": "nickname", "source": "twitch", "color": "#9146ff"}

Put your bot's variables instead of the text and nickname (usually something like %message% and %user%). source is up to 16 Latin characters: twitch, vk, youtube, kick — anything. color is optional.

Example: Twitch → our chat in Node.js

The shortest bridge: reads the Twitch chat without logging in (anonymously) and forwards every message to us. You need Node.js 18+ and one library:

npm install tmi.js
// twitch-bridge.js — run: PW_KEY=pwc_... TWITCH_CHANNEL=name node twitch-bridge.js
const tmi = require('tmi.js');

const KEY = process.env.PW_KEY;            // PartyWatcher chat key — don't hard-code it
const client = new tmi.Client({ channels: [process.env.TWITCH_CHANNEL] });

client.on('message', async (channel, tags, message) => {
  try {
    const res = await fetch('https://partywatcher.de/api/chat/send', {
      method: 'POST',
      headers: { Authorization: 'Bearer ' + KEY, 'Content-Type': 'application/json' },
      body: JSON.stringify({
        text: message,
        username: tags['display-name'] || tags.username,
        source: 'twitch',
        color: tags.color || '#9146ff',
      }),
    });
    if (res.status === 429) console.warn('Too often, the site asks to wait', res.headers.get('retry-after'), 's');
  } catch (e) {
    console.warn('Not sent:', e.message);
  }
});

client.connect();

Example: any Python bot

If your bot is already written in Python (for VK, Twitch or anything else), add one function and call it for every new message:

import os, requests

PW_KEY = os.environ["PW_KEY"]  # PartyWatcher chat key

def to_partywatcher(user, text, source="vk", color=None):
    body = {"text": text[:500], "username": user[:32], "source": source}
    if color:
        body["color"] = color
    try:
        r = requests.post("https://partywatcher.de/api/chat/send",
                          json=body, headers={"Authorization": "Bearer " + PW_KEY}, timeout=5)
        if r.status_code == 429:
            print("Too often, wait", r.headers.get("Retry-After"), "s")
    except requests.RequestException as e:
        print("Not sent:", e)

# in your bot's new-message handler:
# to_partywatcher(author_name, message_text, source="vk", color="#0077ff")

The other way: our chat → Twitch or VK

Connect to our chat with the same key and forward new messages. Important: skip messages with external: true — those are what your own bot brought from Twitch or VK. Otherwise messages will loop.

npm install socket.io-client
const { io } = require('socket.io-client');

const pw = io('https://partywatcher.de/chat', { transports: ['websocket', 'polling'] });
pw.on('connect', () => pw.emit('chat:join', { chatKey: process.env.PW_KEY }));
pw.on('chat:overlay-error', (e) => console.error('Key rejected:', e.error));

pw.on('chat:message', (m) => {
  if (m.external) return;                  // came from Twitch/VK or a bot — don't send it back
  const text = m.masked || m.text;         // with the channel word filter applied
  sendToTwitch(`[PW] ${m.senderUsername}: ${text}`); // your function that posts to the platform
});

To write in a Twitch chat, the bot needs its own Twitch account and token — that is set up on Twitch, not here. For VK — the same, through VK's own API.

Commands, rewards and events for bots

  • Commands !command from the “Builder” only answer messages written in our chat. On Twitch and VK let your own bot handle commands. Our bot's replies come with source: "bot" — you can forward them to Twitch if you like.
  • Channel events (follow, raid, reward purchase) — with the events key, see Events API. For example, your bot can say “Thanks for following on PartyWatcher!” on Twitch.
  • Reward purchases and marking them “done / refund points” — Rewards API.
  • OBS widgets can be controlled with the /timer, /count etc. chat commands only from the streamer's or a moderator's account — moderation commands don't run through the chat key API.

Limits and security

  • At most 20 messages per 10 seconds and 100 per minute per channel. Above that — a 429 reply with a Retry-After header. In a very busy chat, don't forward everything (e.g. skip emote-only messages).
  • Text — up to 500 characters, nickname — up to 32. Messages through the API are marked external, and OBS shows their source label.
  • Keep the key in an environment variable or a config file, not in code and not on stream. If it leaks, create a new one in “Chat API” — the old one stops working at once. More in Security and limits.

Not working?

  • 401 — the key is wrong or old. Check that the header is Bearer pwc_… with a space after Bearer.
  • 400 — empty text: the bot sent the wrong field.
  • Messages arrive twice — the bot runs twice or forwards its own messages back (check external).
