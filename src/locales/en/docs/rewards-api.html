Rewards API

Your own logic on a reward purchase: for example, a bot spins a roulette or switches an OBS scene. The key is the same as for events (studio → 🔔 Events).

Know about a purchase right away

Connect to the events API (“Events” chapter, “Events API” page) and listen for event with type: "reward". Its vars include rewardSlug and redemptionId.

List purchases over HTTP

Every reward has its own address — the 📋 API button in the card copies it:

GET https://partywatcher.de/api/rewards/<channel>/<reward>?status=new
Authorization: Bearer YOUR_KEY
ParameterWhat it is
statusnew, done or refunded. Without it — all.
afterISO time, for example 2026-10-13T18:00:00Z: only purchases after it.

The response is up to 100 purchases, newest first:

[{ "id": "…", "reward": "coinflip", "user": "viewer123", "userId": "…",
   "cost": 50, "message": "", "status": "new", "createdAt": "…" }]

Mark a purchase

POST https://partywatcher.de/api/rewards/<channel>/<reward>/<id>/done
POST https://partywatcher.de/api/rewards/<channel>/<reward>/<id>/refund

done — done, refund — give the points back to the viewer. The status changes in the studio as well.

CodeWhat it means
200Done.
401No key, a wrong key, or a key of another channel.
404No such purchase.
409The purchase was already marked.

Send the key only in the Authorization header, not in the address — otherwise it ends up in logs.
